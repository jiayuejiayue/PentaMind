# 自动化渗透测试浏览器插件开发方案计划书 (PentaMind - Extension)

## 1. 项目概述
本方案旨在规划开发一款用于自动化渗透测试的浏览器扩展插件。该插件将模拟真实用户行为，自动发现和触发页面上的功能点（如按钮、链接、表单等），收集相关数据并发送至LLM（大语言模型）进行安全分析，最终实现漏洞的半自动化或自动化发现。开发将遵循“由浅入深、循序渐进”的原则逐步深化。

## 2. 核心挑战与技术实现思路

### 2.1 如何寻找功能点？
*   **DOM树遍历与特征提取**：
    *   通过DOM API查询所有强交互元素：`<button>`, `<a>`, `<input>`, `<form>`，以及带有 `role="button"`, `onclick` 属性或特定交互类名的元素。
    *   **可见性过滤**：排除 `display: none`，`visibility: hidden` 或被其他元素完全遮挡的隐藏元素，确保提取的是真实可交互的功能点。
*   **事件监听分析 (Hook)**：
    *   在页面加载初期注入脚本，Hook原生的 `addEventListener` 或网络请求API，记录哪些DOM元素绑定了动作，以便更精准地捕获由JS动态生成的交互点。
*   **视觉与结构识别 (LLM辅助)**：
    *   将DOM结构片段或页面截图传递给LLM，让模型根据上下文理解哪部分是“登录与注册”、“评论区”、“后台管理菜单”等，从而进行有针对性的功能点寻找。

### 2.2 如何确保位置与功能点唯一性？
*   **生成唯一标识符 (XPath/CSS Selector)**：
    *   为每个发现的功能点生成精准的 XPath 或 CSS 选择器，以便在后续自动化测试发包或点击时能准确回溯定位。
*   **上下文哈希校验 (Hash)**：
    *   除选择器外，记录元素的文本内容、相邻元素标记、父节点的类名等，生成一个上下文特征值。当目标页面DOM有微调或动态渲染时，可以通过特征相似度定位回原元素，防止错位。

### 2.3 插件能否根据页面去自动开展测试？
*   **支持被动记录与主动探索双模式**：
    *   **被动模式 (Passive)**：平常跟随用户的正常浏览行为，静默记录所有的网络请求与DOM变化，收集功能点但不主动发起攻击。
    *   **主动模式 (Spider/Crawler)**：当用户赋予权限并点击“开始”后，插件根据当前URL自动执行 DFS（深度优先）或 BFS（广度优先）点击遍历。它能检测当前页面类型（如列表页、详情页、表单页），来决定是尝试提交表单还是遍历点击链接。
*   **状态管理与防死循环机制**：在插件的后台脚本（Background Script）中维护一个已访问URL和已点击元素的Hash记录池，避免在同一页面内无限点击（例如点击分页的"下一页"导致的无限循环）。

## 3. 漏洞自动化测试与判断策略

### 3.1 怎么进行自动化测试？
*   **Payload 自动注入与填充**：针对识别出的输入框或URL参数，根据其数据类型（数字、字符串、JSON等）自动填充经典的 Fuzzing Payload（如 `'`, `"`, `<script>`, `../` 等）。
*   **流量拦截与改包**：通过扩展的 `chrome.debugger` 或 `declarativeNetRequest` API 拦截浏览器发出的底层请求，在请求头（Headers）、Cookie 或 Body 中注入测试载荷。
*   **结合 LLM 生成针对性测试用例**：将获取的接口格式（如包含 `user_id`, `role` 的JSON）发给LLM，由LLM返回需要fuzzing的定制化数据包结构，插件在浏览器端构造并发送。

### 3.2 漏洞存在的判断标准：哪些好判断，哪些不好判断？
*   **较易判断的漏洞（适合插件自动化直接报警）：**
    *   **反射型 XSS**：注入特定字符串能在响应页面源码中看到未转义的原样输出。
    *   **常规 SQL 注入（报错/盲注）**：根据明确的数据库报错信息响应，或依据时间延迟（如 `sleep(5)`）进行精确判断。
    *   **敏感信息泄露**：页面源码或接口返回了身份证、手机号、AK/SK配置、明文密码等，正则或规则极易匹配。
    *   **CORS 配置错误**：通过 Origin 反射及相应的 Headers 即可判定。
*   **较难判断的漏洞（高度依赖 LLM 逻辑推理与人工复核）：**
    *   **越权漏洞（IDOR / 水平/垂直越权）**：机器难以单纯通过请求包区分当前操作是否合法，必须借助LLM分析请求参数中的ID与操作意图。
    *   **业务逻辑漏洞**：如并发购买、支付金额篡改、验证码绕过。这些需要特定的时序操作或对业务规则的理解（如修改单价从100变成1）。
    *   **存储型与 DOM 型 XSS**：存储型注入点与触发点分离，且可能在管理后台（依赖 XSS 盲打平台）；DOM型涉及复杂的 JavaScript 污点跟踪执行流，纯黑盒发包难以探测。

## 4. 落地开发演进路线（由浅入深的步骤）

### 阶段一：页面信息收集与感知基础 (V1.0)
*   **目标**：实现页面功能点的**全面获取**与网络接口记录。
*   **研发点**：
    1.  开发基础的 Chrome Extension (基于 Manifest V3)。
    2.  注入 Content Script 解析当前 DOM，提取所有输入框、按钮、超链接并生成唯一标识。
    3.  拦截 Network 流量，收集页面的 API 接口清单 (URL, Method, Headers, Params)。
*   **LLM 交互点**：发送提取的功能点信息给 LLM，让其初步总结：“该页面具备哪些功能领域？”（例：识别出这是个带有文件上传的个人资料页）。

### 阶段二：意图识别与半自动化探测 (V2.0)
*   **目标**：判断功能点作用，针对高价值目标进行人工确认后的自动化测试。
*   **研发点**：
    1.  **LLM 交互点**：传入具体的 API 请求详情和 DOM 元素，让 LLM 判断其潜藏的漏洞类型。例如 LLM 反馈：“`/api/download?file=xxx` 接口可能存在目录遍历”。
    2.  插件前端(Popup/DevTools面版)列出 LLM 推荐的测试点。
    3.  用户点击“开始探测”，插件针对选定元素自动填充 LLM 推荐的测试 Payload。
    4.  收集测试后的响应结果，再次反馈给 LLM，由 LLM 判断是否存在漏洞。

### 阶段三：全自动化 Spider 探索引擎 (V3.0)
*   **目标**：插件具备自动接管页面的能力，实现在指定域名边界内的自动化遍历和黑盒发包。
*   **研发点**：
    1.  基于状态机的自动点击爬虫策略。优先交互表单和带参请求，忽略静态页面。
    2.  自动填充伪造测试数据机制（如假邮箱、测试手机号），确保后续业务流能继续进行。
    3.  针对前面判断为“易发现漏洞”（XSS、报错注入、信息泄露）进行**完全静默探测**，一旦命中漏洞指纹，即时推送到面板告警。

### 阶段四：深入交互与复杂逻辑分析 (V4.0)
*   **目标**：引入会话动作录制和业务逻辑漏洞辅助分析，打造智能 Agent 雏形。
*   **研发点**：
    1.  实现多步操作录制（宏录制，如：登录 -> 添加商品入网购车 -> 结算准备）。
    2.  将这段行为全集发给 LLM，由其分析提炼逻辑链条。
    3.  **LLM 交互点**：LLM 具备 Agent 能力，指导插件执行：“在这几步重放时，把第2步请求头里的 Cookie 的角色字段替换掉，看看能否越权访问第3步的接口”。插件按指示重放、对比并输出报告。
